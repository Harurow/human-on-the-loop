# ADR-009: レビューは回帰集を通してから新規探索。PASS 周の MINOR は反映しない

**状態**: Accepted（2026-09-05）。**「PASS まで反復」の部分は ADR-011 で Superseded**（最大2周に有界化）／**関連**: `plans/regression-scenarios.md`・`plans/review-backlog.md`

## 文脈
fresh context の敵対的レビュー → 自律修正のループで品質を上げてきたが、43〜51周で **MAJOR 23件のうち14件が「前の周の修正が原因」**になり、指摘が3箇所で振動して収束しなくなった。

## 決定
1. レビュアーには**ファイル一式と回帰シナリオ集**を渡し、**全シナリオを通してから**新規探索させる（ADR とレビュー履歴は**渡さない** — 敵対性を保つため）
2. **MAJOR の定義は「具体的な実行系列を示せるもの」**。示せない曖昧さは MINOR
3. **PASS した周の MINOR / NIT は反映しない**。`plans/review-backlog.md` に積み、次にフレームワークを変更するときの入力にする
4. 修正は「規則を足す」より「**衝突を畳む・不要な規則を削る**」を優先。同じ箇所を2周続けて触ったらパッチをやめて**表として作り直す**
5. MAJOR を直したら**回帰シナリオを1件追加**し、振る舞いの判断をしたら **ADR を1枚書く**
6. 指摘が ADR と矛盾する場合は、そのまま適用せず「再検討の条件を満たすなら supersede」「満たさないなら却下＋ADR に履歴を1行」

## 理由
- 回帰は fresh context のサンプリングでは原理的に検出できない（毎回ちがう箇所を見るため）。明示的なシナリオ集が要る
- PASS 後に MINOR を反映すると対象 commit がずれてもう1周必要になり、その修正がまた次の周の MAJOR を生む（47→48→49→50周が実例）
- 規則の追加は組み合わせを増やす。同じ箇所の指摘が続くのは「散在した規則にパッチを当てている」症状
- ADR が無いと、レビュアーは退けた案を何度でも提案し、修正する側はそれを鵜呑みにする（本 ADR を書いた直接の理由）

## 退けた案
- **レビュアーに ADR とレビュー履歴を渡す**: 経緯を知ったレビュアーは「既に検討済み」に引きずられ、敵対的レビューの検出力が落ちる。照合は**修正する側**の責務にする
- **MINOR も全部直してから PASS を取る**: 上記のとおり収束しない
- **レビュー自体をやめて実地ドライランに一本化する**: ドライランは実行環境・要件の書き方など別クラスの欠陥を出すが、クラッシュ再開や PM 経路の網羅は机上でしか通せない。**併用する**

## 再検討の条件
2周続けて「回帰 NG ゼロ・新規 MAJOR ゼロ」になり、かつ次の変更が構造に触らない小さなものだけになったとき（レビューの重さを下げてよい）。
