# ADR-010: シェルスクリプトはロケールを C に固定する

**状態**: Accepted（2026-09-05）／**関連**: 回帰 H-1・H-2

## 文脈
`scripts/check-consistency.sh` と `install.sh` は日本語を含む文字列を扱う。macOS 標準の `/bin/bash` は 3.2 で、ユーザーの端末は通常 `LANG=ja_JP.UTF-8`。

## 決定
スクリプト冒頭で `export LC_ALL=C` / `export LANG=C` に固定する。多バイト文字はブラケット式 `[...]` の中に書かず、必ず代替 `(a|b)` を使う。文字列の切り出しは `awk` の `index` / `substr` で行う。

## 理由
- UTF-8 ロケール下の bash 3.2 は `$var` の直後に多バイト文字が続くコードでパーサが変数名の終端を誤検出し、`set -u` と組み合わさって `unbound variable` で異常終了する（48周 MAJOR。実際に手元の端末で check スクリプトが完走しなかった）
- C ロケールではブラケット式が1バイトずつ解釈されて文字列を壊す
- 両方を同時に避けるには「C に固定 ＋ ブラケット式を使わない」しかない。**呼び出し側のロケールに依存させない**ことが要点

## 退けた案
- **UTF-8 ロケールに固定する**: bash 3.2 のパーサ不具合を踏む
- **ロケールを触らず C 前提で書く**: 動く/動かないが呼び出し側の環境依存になる（実際に「Claude Code の Bash では動くが人間の端末では落ちる」状態だった）

## 再検討の条件
対象環境の bash が 4 以降に揃ったとき。
