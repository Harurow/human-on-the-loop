# ADR-008: 台帳（docs/）は更新のたび commit し、WIP の破棄は実装ファイルに限る

**状態**: Accepted（2026-09-05）／**関連**: 回帰 B-5b・D-1・D-4

## 文脈
実装ループでは `git add -A` を禁止し、タスクごとに変更ファイルを明示指定して commit する（WIP の巻き込みを防ぐため）。一方、方針変更の反映や修正タスクの挿入は docs/ 配下の台帳を書き換える。

## 決定
- **台帳（tasks.md / spec.md / design.md / log.md）を更新したら、その場で commit する**（方針変更の反映・修正タスクの挿入・バックログ整合のいずれも）
- 再開時の WIP の**破棄はそのタスクで変更した実装ファイルに限る**。docs/ 配下は破棄しない

## 理由
台帳を未コミットのまま実装 WIP と混ぜると、再開時に「破棄してやり直す」を選んだ瞬間に**人間の指示そのもの（interrupt の記録・挿入したタスク・更新した設計）が消える**（51周 MAJOR）。しかも消えたことは git log にも trail にも残らないので、以後どの検査でも検出できない。

## 退けた案
- **フェーズ遷移の commit（Step 6）にまとめて含める**: 遷移まで数タスクあるため、その間のクラッシュで同じ問題が起きる
- **破棄の判断自体をやめて常に引き継ぐ**: 壊れかけの実装を引き継ぐコストが高い（P5 が「判断して記録する」としている理由）

## 再検討の条件
なし（作業消失クラスの防御なので、削るには同等の代替が要る）。
