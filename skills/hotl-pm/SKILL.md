# HOTL PM（旗振り役）

複数プロジェクトのポートフォリオ管理を行う。**PM は自分の状態を一切持たない**: 状況はワークスペース直下の `*/docs/hotl.state.json` を glob して**毎回その場で導出**する。セッションがいつ切れても、次のセッションは glob し直すだけで同じ品質で再開できる（コンテキストの引き継ぎ不要）。

**ワークスペース**: この SKILL.md がインストールされたフォルダ（通常は cwd）。**プロジェクト** = 直下のサブディレクトリのうち `docs/hotl.state.json` を持つもの（各プロジェクトは独立した git リポジトリ）。個々のプロジェクトの進め方は `hotl` スキル（同じ `.claude/skills/` 内の `hotl/SKILL.md`）が唯一の正であり、PM はそれを「どのプロジェクトに・どの実行形態で適用するか」を采配するだけ。

## Step 1: ポートフォリオ把握

`*/docs/hotl.state.json` を glob し、各プロジェクトの `project` / `phase` / `updated_at` を読む。
**この時点で state 以外のファイルを読まない**（詳細が必要になったら、処理対象のプロジェクトの trail 末尾だけを読む — hotl の読み込み規律と同じ）。

## Step 2: メッセージの振り分け

1. **状況確認**（「状況を教えて」等） → 下記「状況一覧の書式」で報告してターンを終える
2. **特定プロジェクトへの指示**（名前・文脈から特定） → Step 3 へ。特定できなければ一覧を示して確認する
3. **新規開発の意図** → プロジェクト名（kebab-case）を決めて直下にサブディレクトリを作成し、そこを対象に Step 3 へ
4. 対象が確定したら、以後そのプロジェクトの処理は **hotl の SKILL.md に従う**（そのサブディレクトリをプロジェクトルート＝cwd として扱う）

## Step 3: 実行形態の選択

対象プロジェクトの `phase` で分岐する:

- **人間との対話が必要な区間**（`hearing` / `requirements` / `awaiting_approval`） → **メインループで** hotl を実行する。ヒアリングの質問と承認ゲートは人間と直接やり取りする必要があるため、サブエージェントに任せない。同時に対話できるのは1プロジェクトだけ
- **自律区間**（`specification` / `design` / `development`） → **サブエージェントに委譲**する（Step 4）。複数プロジェクトが自律区間にあれば**並列に**起動してよい
- **done** → 完了報告のみ。新要望があれば hotl のイテレーション手順（メインループで interrupt 記録 → 承認リセット → 差分ヒアリング）へ

## Step 4: 自律区間のサブエージェント委譲

サブエージェント1体につき1プロジェクト。プロンプトに必ず含めるもの:

- プロジェクトの**絶対パス**（そこを cwd として作業する）
- hotl スキルの**絶対パス**（その `SKILL.md` を Read し、Step 4（状態読み込み）から従う）
- **停止条件**: 人間の入力が必要になったら（承認ゲート・BLOCKED・検証キャップ超過・要件矛盾によるゲート戻り）、**自分で人間に聞かず**、state / trail を保存してターンを終え、最終出力で「何を人間に確認すべきか」を返すこと
- 最終出力は人間向けメッセージではなく **PM への報告**（現在 phase・完了タスク数・要確認事項）であること

ルール:

- **同一プロジェクトに2体以上を同時に起動しない**（進捗の正本 tasks.md が競合する）。前回のサブエージェントが途中で死んでいても、新しい**1体**を起動すれば hotl の再開性（state + trail + tasks.md）で続きから進む
- サブエージェントのコンテキストが尽きて途中終了した場合も同じ扱い: 新しい1体に「続きから」を渡すだけでよい
- 完了・停止の報告を受けたら、要点を人間に中継する。**人間の判断が必要な項目（承認待ち・BLOCKED 等）は明示して伝える**

## 状況一覧の書式

```
📋 ポートフォリオ（N プロジェクト）
- <project>: <phase>（更新: <updated_at>）— <一言: 承認待ち / 自律実行中 / 人間の判断待ち / done>
```

## PM の規律

- **状態を作らない**: ポートフォリオ一覧ファイル・進捗集計ファイルを書かない。正本は各プロジェクトの state / tasks.md / trail であり、集計は毎回 glob で導出する
- **深読みしない**: PM が読むのは各プロジェクトの state と、処理対象の trail 末尾だけ。コード・仕様の中身を読むのはサブエージェントの仕事
- **PM 自身の trail は持たない**: PM の采配（委譲・中継）で記録に値する判断は、対象プロジェクトの trail に記録する（プロジェクトに属さない判断は原則発生しない設計にしている）
- 複数セッションから同じワークスペースを同時に操作する運用は想定しない（必要になったら hotl 側の排他制御 — 保留中の B-7 — を先に導入する）
