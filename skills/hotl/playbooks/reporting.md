# 報告プロトコル（ランタイムアダプタ）

human-on-the-loop の原則: 人間は「ループの上」にいる。報告は**非ブロッキング**であり、返信を待たない。
人間の返信を待ってよいのは、ヒアリング中の質問と要件承認ゲートの2箇所だけ。

## ランタイム検出

- `/workspace/group` ディレクトリが存在する → **nanoclaw**（Discord 経由のコンテナ内実行）
- 存在しない → **Claude Code**（ターミナル）

## ランタイム別の届け方

| | nanoclaw | Claude Code |
|---|---|---|
| 途中報告 | `send_message` ツールで即時送信（実行は止めない） | 通常のテキスト出力 |
| 最終報告 | ターン終了時の最終メッセージ | ターン終了時の最終メッセージ |
| ヒアリング質問 | 質問を送ってターン終了（返信待ち） | 質問して待つ。AskUserQuestion も可 |
| 承認ゲート | 「『承認』と返信してください」でターン終了 | AskUserQuestion（承認 / 修正依頼 / 質問） |

**共通ルール**: すべての報告は、送信と同時に同内容を `docs/log.md` に追記する（`## YYYY-MM-DD HH:MM` 見出し付き。時刻は `date +"%Y-%m-%d %H:%M"` の実行結果を使う）。log.md が永続記録であり、セッションが変わっても経緯を追える唯一の場所。

## フェーズ完了報告の書式

3〜6行で簡潔に:

```
✅ <フェーズ名> 完了
主要な決定: <最大3点、箇条書き>
成果物: <ファイルパス>
次: <次フェーズ名>（自律区間の場合は「このまま続行します」）
```

## 開発中間報告の書式

タスク3件完了ごと、またはブロッカー発生時:

```
🔨 開発中: <完了タスク数>/<総タスク数>
直近の完了: <T-n タスク名（最大3件）>
ブロッカー: <あれば。なければ省略>
```

## 介入の案内

自律区間の**開始時（承認直後の報告）に1回だけ**、次の一行を添える。以後の報告には毎回付けない（ノイズになる）:

> 方針変更や停止はいつでもメッセージでどうぞ（返信は不要です）

## 割り込みへの対応

実行中にユーザーからメッセージが来た場合:

1. 内容を判断する。**進行の停止指示**なら現在のタスクを安全に閉じて state を保存し、停止を報告する
2. **方針変更（仕様・設計・タスクレベル）**なら、影響範囲を判断して該当ドキュメント（spec / design / tasks）と state を更新し、変更内容と理由を log.md に記録してから続行する
3. **要件レベルの変更（要件の追加・削除・意味の変更）**は承認済みハッシュを無効化する。`approval` をリセット（`approved: false`、旧記録を log.md へ退避）し、要件を更新して**承認ゲートを再実行**する（SKILL.md Step 7 の例外に対応）
