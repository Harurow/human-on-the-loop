# セキュリティ横断チェックリスト（最終受け入れ検証の非機能横断チェック用）

レビュアーへ: あなたの仕事は**攻撃面の棚卸しと指摘のみ**。修正はしない。渡された「リポジトリ」「requirements.md のセキュリティ前提（NR）」「design.md」に各項目を適用し、前提を超える露出・欠陥を指摘する。

## 1. 攻撃面の棚卸し

- [ ] 入口を列挙したか: ネットワーク待ち受け（ポート・バインド先・認証の有無）、ファイル入力、外部サービスからの入力（API 応答・スクレイピング結果・LLM 出力）、設定ファイル、CLI 引数
- [ ] 各入口について、要件のセキュリティ前提（公開範囲・データ機微度）と実装が一致しているか（例: 「家庭内 LAN のみ」なのにインターネットへ露出しうる設定になっていないか）

## 2. 入力の扱い

- [ ] 外部入力（特に LLM 出力・スクレイピング結果）を HTML / SQL / シェル / OS コマンド / ファイルパスへ渡す箇所で、エスケープ・パラメタ化・検証があるか
- [ ] パストラバーサル・任意ファイル読み書きの経路がないか（配信ディレクトリの外に出られないか）
- [ ] サイズ・件数・再帰の上限がない入力で資源枯渇（メモリ・ディスク・API 課金）を起こせないか

## 3. 秘密情報とデータ

- [ ] 秘密情報の保管場所・読み込み経路・ログ/生成物への非出力が守られているか（追跡ファイル・ログ・出力物を実際に検索する）
- [ ] 保存データの機微度に見合う保護か（バックアップ・共有・配信先で意図せず露出しないか）

## 4. 依存と実行環境

- [ ] 依存の既知脆弱性チェック（pip-audit 等）がツールチェーンに含まれ直近で通っているか。含めない設計判断がある場合はその理由が妥当か
- [ ] 常駐プロセス・スケジューラの権限が最小か（不要な書き込み権限・全インタフェースへのバインド等）

## 判定の出力書式

```
判定: PASS / FAIL
攻撃面: <列挙した入口の一覧（各1行）>
指摘:
1. [棚卸し|入力|秘密情報|依存環境] <対象:箇所>: <指摘内容>（重大度: CRITICAL/MAJOR/MINOR、修正の方向性: <一言>）
2. ...
```

CRITICAL/MAJOR が1件でもあれば FAIL。MINOR のみなら PASS（MINOR は reporting.md の3分類で②〔バックログ登録〕か「最終報告で開示」として対応記録を残す）。
