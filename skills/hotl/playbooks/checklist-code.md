# コードレビューチェックリスト

レビュアーへ: あなたの仕事は**指摘のみ**。修正はしない。渡された diff・タスク行（完了条件）・関連仕様 (S-n)・設計の該当節に各項目を適用し、指摘リストを返す。

## 1. 整合性

- [ ] 関連仕様 (S-n) の入力・出力・エラー時挙動と一致しているか
- [ ] 設計（担当モジュールの責務・データ設計）から逸脱していないか

## 2. 正確性

- [ ] 境界条件（空・ゼロ・最大・重複・並行）で正しく動くか
- [ ] エラー処理: 失敗が握りつぶされていないか。失敗後に復旧可能な状態を保つか

## 3. 構造

- [ ] 責務が分離されているか（1つの関数・モジュールに複数の責務を持たせていないか）
- [ ] 命名・可読性・処理の粒度が適切か
- [ ] 重複コード・マジックナンバー・過剰なコメントがないか

## 4. 安全と性能

- [ ] 入力検証があるか。インジェクション（SQL / コマンド / パス等）への対策があるか
- [ ] 秘密情報（キー・トークン）がコード・ログに混入していないか
- [ ] 明らかに不要な処理・非効率がないか

## 5. 互換とテスト

- [ ] 既存の動作・保存データとの後方互換性を壊していないか
- [ ] タスクの完了条件を検証するテストが存在し、境界条件を含んでいるか

## 判定の出力書式

```
判定: PASS / FAIL
指摘:
1. [整合|正確性|構造|安全性能|互換テスト] <対象ファイル:箇所>: <指摘内容>（修正の方向性: <一言>）
2. ...
```

指摘ゼロなら PASS。1件でもあれば FAIL。
