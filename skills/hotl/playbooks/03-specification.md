# Phase: 仕様化（自律区間）

**入力**: `docs/requirements.md`（承認済み）
**成果物**: `docs/spec.md`（`templates/spec.md` に従う）

## 進め方

1. `templates/spec.md` をコピーして雛形にする
2. 各要件 (R-n) を振る舞い仕様 (S-n) に展開する:
   - **入力・出力・エラー時挙動**を必ず明記する
   - 1要件が複数の仕様項目になるのは普通。逆に対応要件のない仕様項目は書かない（スコープクリープ）
3. 外形を定義する: CLI ならコマンド体系と出力例、Web なら画面一覧と遷移、API ならエンドポイント
4. データモデル素案を書く（詳細な設計は次フェーズ。ここでは保存すべき情報の構造まで）

## トレーサビリティ

要件トレーサビリティ表を埋め、**対応する仕様のない要件がゼロ**であることを確認する。
漏れがあれば仕様を追記してから完了する。

## 判断に迷ったら

承認済み要件の範囲内で最も単純な解釈を選び、その判断を spec 内と log.md に記録する。
**人間には聞かない**（自律区間）。要件自体に矛盾を発見した場合のみ例外で、reporting.md の割り込みルールに従い承認ゲートに戻る。

## 完了

SKILL.md Step 6 の遷移ルールを実行（state 更新 → commit → 報告）し、
**同一ターン内で** `04-design.md` を Read して設計フェーズを続行する。
