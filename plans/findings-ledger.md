# 指摘台帳（1指摘 = 1行。対応と、その対応が後に何を生んだかを追跡する）

**目的**: 修正の前に「同じ領域で過去にどんな対応をして、それがどうなったか」を照合し、**同じ対応を繰り返さない**。回帰シナリオ集（何が壊れてはいけないか）・ADR（なぜその決定か）と並ぶ3つ目の記録で、これだけが「**対応の因果**」を持つ。

## 記入規則

- **レビュアーは指摘ごとに領域タグを付ける**（下の語彙から。複数可）。修正する側はタグで本台帳を引く
- 対応を適用したら**その場で1行追加**する（`その後` は空欄）。後の周でその対応が原因の指摘が出たら、元の行の `その後` に `→ <新しい指摘 ID>` を書く（**因果の鎖を残す**）
- レビュアーの修正案は**症状の裏付けとして読む**もので、**対応はそのまま採用しない**。台帳と ADR に照合して自分で決める（振動の多くは修正案の逐語適用から生じた）

## 領域タグ（閉じた語彙。`scripts/check-consistency.sh` が検査する）

| タグ | 領域 |
|---|---|
| GATE | 承認の判定（再開語・時点・未反映の修正依頼） |
| BODY | 本文待ち・再確認中（ゲートの選択後の待ち状態） |
| ROUTE | 人間の入力の経路（phase × 内容 → 処理先）・割り込み分類 |
| CYCLE | 検証の周回・キャップ・起算点・再周判定 |
| TRIAGE | 指摘の3分類・MINOR の扱い・タスクの挿入位置 |
| UX | UX ウォークスルーの経路（スコープ外・見送り） |
| PM | hotl-pm の委譲・区切り・受領規則・inbox |
| RESUME | クラッシュ再開・台帳の commit・WIP |
| IDS | ID 規約・差分更新・サブエージェントへの入力 |
| SELECT | 選択式（AskUserQuestion）の適用範囲 |
| SCRIPT | scripts/check-consistency.sh |
| INSTALL | install.sh |
| ENV | 実行環境（ロケール・bash 版・symlink） |
| REQ | 要件の書き方・チェックリスト |

## 修正前の照合手順（PRINCIPLES 手順4 から参照）

1. 指摘の領域タグで本台帳を引き、同じ領域の過去行を**全部**読む
2. 次のどれに当たるかを判定して、対応を決める:
   - **(a) 過去の対応と同種で、その行の `その後` に `→` がある** — その対応は後で欠陥を生んだ。**同じ対応は禁止**。畳む・削る・表にする、のどれかで別の対応を選ぶ。決められないなら ADR を supersede する判断として扱う
   - **(b) ADR が退けた案と同じ** — 修正しない。ADR の「再指摘の履歴」に1行
   - **(c) 同じ領域が3周続けて出ている** — パッチ禁止。その領域を表・状態遷移として作り直す（`check-consistency.sh` が WARN を出す）
   - **(d) 上のどれでもない** — 通常どおり修正する
3. 対応を本台帳に1行追加する（ID・周・タグ・症状・対応）
