# レビュー台帳

フレームワーク（`skills/` 配下・`install.sh`・`PRINCIPLES.md`・`README.md`）に変更を加えたら、PRINCIPLES.md「フレームワーク自体の変更プロセス」のループを回す。**その1周ごとに1行をここに追記する**。

この台帳の目的は、「残作業がゼロか」を commit メッセージの読み解きではなく**1箇所を見て判定できる**ようにすること。`plans/` と本ファイル自身の更新はフレームワークの変更ではないので、レビューループの起点にはならない。

## 「残作業なし」の判定条件

次の3つが同時に成り立つときに限り「全て完了・残作業なし」と言える:

1. **最新の敵対的レビュー行が PASS**（CRITICAL / MAJOR ゼロ）で、**その周の対象 commit が HEAD と一致**する — PASS 後に MINOR/NIT を反映した場合もフレームワークの変更なので、対象 commit がずれる。もう1周必要
2. その PASS 以降に**使う側の視点のレビューが1回**実施済みで、指摘対応が振る舞いを変えていない（変えたら 1 に戻る）
3. **未消化**（次周送り・保留）の指摘が残っていない

## 記入規則

- 1周1行。周を回したその場で追記する（後からまとめて書かない）
- **対象 commit**: レビュアーに読ませた時点の HEAD。**対応 commit**: 指摘を反映した commit
- **モデル**: 既定（最上位）を使う。過負荷等でやむを得ず別モデルを使った周はモデル名を明記し、**最終 PASS は既定モデルで取り直す**
- **結果**: `C/MA/MI/N` = CRITICAL / MAJOR / MINOR / NIT の件数。`0/0/-/-` のように MAJOR 以上ゼロなら PASS
- **未消化**: その周で先送りにした指摘。無ければ `—`
